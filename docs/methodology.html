Projection methodology

How the publicly described system works end-to-end — and how our original engine/ package mirrors each stage without any proprietary code.

The pipeline (as officially described)

#StageOfficial descriptionOur original module
1 Ingest Historical salaries × performances DB; Vegas lines from seven books; news/lineups in real time; league stats. S11 S17 data.py (validated CSV) + documented legal sources in Data sources
2 Expectation model Fit E[points | salary] from the historical DB — “if Mahomes costs $10,000, we know he should produce X points”. S11 ExpectationModel — monotone binned regression, mean fallback, guardrails
3 Metric layer Plus/Minus family, Consistency, Upside, Duds, Bargain Rating, Opponent +/−, Pts/Sal… S11 S12 metrics.py — 14 functions, both official Duds/Upside variants (I4/I5)
4 Projections Median, ceiling (85%), floor (15%); NFL comps-based (30 sims), NBA volatility-based; real-time updates; conditional scenarios; custom upload/aggregation. S11 S12 S7 S8 Caller-supplied medians + simulation percentiles; scenarios = re-run with altered inputs
5 Player model Weight factors (Vegas Score, order percentile, park factor…) → ratings → backtest vs historical +/− → R². S17 WeightedPlayerModel — user weights, z-scores, backtest() returns r/r²/n
6 Trends research Filter the historical DB; read Count / Avg Exp / Avg Act / Points +/− / Consistency; distrust small samples. S14 trends.run_trend() — predicate builder + confidence flags
7 Optimizer Maximize projections under cap with stacks, groups, exposures, ownership inputs; min-spend ≈ 99%; QB stack + bring-back pattern. S16 LineupOptimizer — exact DFS search + jittered restarts; all constraint types tested
8 Simulation (SimLabs-style) Simulate games k-times → lineup pool → shape to field → simulate contests k-times → rate lineups 0–99 vs universe; weight sliders. S19 SlateSimulator — seeded lognormal draws, field model, project_rel/own_rel 0–99, opt-rate
9 Scoring truth Points computed under official DK/FD rules (PPR vs half-PPR, bonuses). scoring.py — transcribed from official pages only (S33/S34/S46; I12)

What parity we have — and what we don’t

PARITY Metric semantics

Every published formula reimplemented and tested against glossary examples.

PARITY Architecture pattern

Weighted model + R², trends with confidence rules, optimizer input set, sim pipeline steps.

PARTIAL Projection accuracy

Same methods, different inputs: no proprietary features (ShotQuality, news sentiment), no historical DK/FD salary archive yet.

GAP Their weights & formulas

Position projection formulas, factor library beyond named examples, Pro Trend booleans, ownership model — all non-public (I15).

Never claimed This project does not claim to reproduce FantasyLabs’ actual projection numbers. It reproduces their documented definitions and system shape, then lets you plug in your own legally obtained data to reach comparable rigor.
